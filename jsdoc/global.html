click function Function to be triggered when clicking in a specific column, etc.
dblclick function Function to be triggered when double-clicking in a specific column, etc.
bgcolor string Background color of the column as an HTML color code (e.g., "#123ABC"). If only one color code is provided, Lex'it automatically calculates a different shade of that color for the odd rows. However, this does not work with literal color names (e.g., "green"). It is also possible to specify the colors for both odd and even rows explicitly by providing a two-element array with the two colors in sequence: ["#123ABC", "#ABC123"].
button string Place a button in a column with the specified name as a string. It is also possible to use the content of the column as the button name: for this, an empty string should be provided for the name ("button": ""). The functionality of the button must be specified using the 'click' parameter.
button_tooltip string Add a tooltip to a button, visible on mouseover. This is useful for explaining the function of a button if the button's name is insufficient (e.g., due to a short name).
cell_tooltip string Add a tooltip to a cell, visible on mouseover. This is useful for indicating that clicking on a cell has a function..
choosefrom array Turn the search box of the specified column into a select box. The values to choose from can be specified in two ways: [1] As an empty array, in which case the tool will automatically retrieve the unique values from the database (e.g., {"choosefrom": []}). [2] As an array of string values. Since the select box will have "Choose" as its first value, "Choose" must also have an underlying value. This 'neutral' value should be the first element in the array, and if no value needs to be assigned, an empty string will suffice (e.g., {"choosefrom": ["", "1", "2", "3"]}, where "" will be the underlying value for "Choose").
choosefrom_labels object Declare labels for the values of a select box. This allows the incomprehensible values expected by the database to be made understandable to the user.
select_trigger_event string An editable cell where only a limited number of values are allowed is typically edited via a select box. With this parameter, you can declare which mouse event should trigger the display of the select box. The default is 'mouseover'.
class string Assign a class to a column, for example, to style the cells of the column. This could include default classes declared in css/lexit_table.css, such as those used for centering content in cells. Lex'it provides some default classes, such as 'inlfont10pt' (for displaying the INL font in 10 pt) or 'inlfont' (this one without a font-size specification).
nice_name string When a column has a technical, non-user-friendly name, you can give it a more user-friendly name for display using this parameter.
colsort string If this is not null, the table will be immediately sorted by this column upon initialization. If multiple columns are specified, the table will be sorted by all these columns. The possible values are 'asc', 'desc', or null (default). Note: If sorting by multiple columns at once, the priority is determined by the order in which the columns to be sorted are specified. It is better and more organized to specify the sorting columns in the table settings using the "columns_sorting" parameter (see there).
contextmenu object Context menu that should appear when clicking on a cell. For more information about the context menu object, see the documentation, see: https://swisnl.github.io/jQuery-contextMenu/docs.html)
copy_upon_insert object If this is true, the content of this column will be copied during a Search&Add action (insert). Columns with this setting set to false will not be included in the insert.
editable boolean Editability of a column.
editcallback function Callback function to be called after a user edits a cell. Note: This is different from 'editfunc'. 'editfunc' is used to modify the behavior of the edit function, while 'editcallback' is executed last, after 'editfunc'.
editfunc function Custom function to be executed after editing a cell. This function is intended to replace the default handling of cell input: normally, the software would update the edited cell directly in the database, but when the screen table is a view, other tables need to be updated instead, and this can be declared in 'editfunc'.
editrefresh array List of tables that should be refreshed after editing a cell.
edittrigger string Regex that the edited cell content must match to trigger the 'editfunc'. If 'edittrigger' is null, 'editfunc' will always be triggered.
editpreprocess string Function for preprocessing an entered value before Lex'it inserts it into the database.
editerrorhandler function Handler that is called when editing an editable field causes an error.
ellipsis boolean Ellipsis. When a cell contains a lot of text, ellipsis can be enabled: only a portion of the text will be displayed. On mouseover, the full content of the cell will be shown.
ellipsis_delay integer Ellipsis. When ellipsis is applied and the user moves the mouse over the table, the cells open one after another, causing rows to swing open and closed, which can be very distracting. This also makes it difficult to select a row, as nearby rows keep opening and closing. One solution is to set a delay, so that the expansion of a row only happens if the mouse is still hovering over the cell after a specified duration. If not, the cell will not expand.
ellipsis_width string 'max-width' attribute for ellipsis.
ellipsis_height string 'max-height' attribute for ellipsis. When this value is exceeded by the cell content, a scrollbar will appear.
ellipsis_unwrap boolean Ellipsis unwrap. Determines whether an ellipsis cell should expand on mouseover or not. (default: true)
ellipsis_keep_selected_unwrapped boolean Ellipsis: Should a selected row remain unwrapped instead of automatically wrapping on mouseout? (default: true)
filter string Column filter that should be applied immediately upon initializing the table. To maintain the filter after initialization, set 'keepfilter': true as well.
flexible_visibility boolean If this is 'false', a user cannot change the visibility of a column (e.g., useful when a hidden column contains information not intended for the user).
keepfilter boolean If this is 'true', the filter (from the 'filter':... parameter) will be reapplied when the 'RESET' button is clicked. If you want to prevent the filter from being modified in the meantime, set "searchable": false for the same column.
query_builder_allowed boolean If this is 'false', the query builder will be disabled by CTRL+click in the search field.
query_builder_values object Declare the search values (keys) to be shown in the query builder, and their translation into database-understandable values (values) to construct a well-formed query.
query_builder_processor function Function to modify the query formulated by the query builder before it is sent to the database.
query_builder_settings object Settings for the query builder (if the default behavior needs to be adjusted). Parameter 'grid': true/false determines whether the search values should be displayed as a grid. Parameter 'preselected' specifies which value should be preselected in the query builder. Parameter 'autostart': true/false determines whether the query formulated by the query builder should be immediately sent to the database when clicking OK.
searchable boolean Searchability of a column.
sortable boolean Sortability of a column.
searchpreprocess function Function to be triggered when a search is applied to a given column. Example: automatically convert the search value to lowercase (this becomes the effective search value).
render function Modify the text of a cell before it is displayed on the screen. This is purely for rendering purposes. It does not affect the underlying data, so search queries are not influenced by this function
textcolor string Color that the text should have in a given column.
textfont string Font-family for a given column.
textsize string Font-size for a given column.
textstyle string Font-style for a given column.
textweight string Font-weight for a given column. See the example at 'textstyle'.
validator string When using select boxes, it may happen that a user accidentally clicks a value. To prevent this, you can enforce in the configuration that the user must press a specified key while making their selection. If the user does not press this key when making a selection in the select box, the choice will be rejected. This validation key can be specified as 'validator'.
visible boolean Visibility of a column. The visibility of a column can be changed by the user in the interface. To prevent this (e.g., because a column contains 'secret' information), you should also set "flexible_visibility": false.
width string Width of a column. This can be specified in 'px', but a relative value (in '%') can also be provided.

group string If you want to group tables into subcategories in the tables menu (e.g., a category 'task tables', a category 'lookup tables', etc.), it is sufficient to assign a 'group' to the relevant tables. All tables that share the same group name will be grouped together in the table selection menu, with this group name as the header.
header_color string By default, the header of a table has a light gray background. However, with 'header_color', a custom color can be specified. When multiple tables are displayed on the screen, a unique color makes a table easier to recognize. If you don't want to choose a color yourself, Lex'it can select one automatically: set 'header_color' to 'auto'.
nice_name string If a table has an unattractive 'technical' name, * it can still be displayed with a nicer name in the interface. * Specify this name using this setting.
top integer If declared, the (top-left corner of the) table will be positioned * at the specified vertical position.
left integer If declared, the (top-left corner of the) table will be positioned * at the specified horizontal position.
displaylength integer By default, a table displays 10 rows at a time. The user can manually change this number in the GUI. However, if you want a different default number of rows without having to adjust it manually each time, you can specify it using 'displaylength'.
displaylength_menu array Define the options available in the 'Show ... rows' menu (in the table header). * To display all rows, use the value -1.
pagingtype string Define the paging type of a table (numbers, simple, simple_numbers, full, full_numbers, first_last_numbers). The default is 'full_numbers'.
viewtype string Define the default display mode of the table: 'table' (normal) or 'form' (form view). The default is 'table'.
formgrid object Declare a form as a custom view for a table (this is explained in detail in the manual).
info string To provide more information about a table in the table overview, define the details here. This information will appear in the menu under 'Choose a table'.

Use the "grouping_column" parameter to specify the column name for grouping. Note: This parameter only makes groups visually distinguishable on the screen. To actually group the data, the table must be pre-sorted by the same column.

viewtype_button boolean Show or hide the "Form/Table View" button (default: true)

help_button boolean Show or hide the "?" button. (default: true)
